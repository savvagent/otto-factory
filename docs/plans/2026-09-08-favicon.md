# Favicon — a real icon set derived from the logo mark

## Goal

Replace the placeholder `web/static/favicon.svg` with a small-scale composition derived from the
brand mark, ship the full multi-format icon set browsers and platforms expect, and wire it up from
`web/src/app.html`.

## Status — 2026-09-08

✅ Shipped in `savvagent/otto-factory#45`.

**Spec:** `docs/specs/2026-09-08-favicon-design.md` — read it first. This plan implements it
exactly.

## Global Constraints

- `web/` conventions: `adapter-static` (no SvelteKit server), so nothing in this change may add a
  server-side dependency. `app.html` is the only source file touched.
- No AI self-attribution anywhere (commits, comments, docs).
- Run `npm run lint` (prettier) before committing the `app.html` change.
- This change touches only `web/static/` (binary/vector assets) and `web/src/app.html` — no SQL, no
  MCP tool, no console route, no migration, no config surface. Tenant isolation, metering, and
  public-interface rules do not apply; no cross-org test and no `of-billing::classify` step needed.
- Gates: `npm run check` (svelte-check + tsc), `npm run lint` (prettier), `npm test` (vitest —
  exercises the Cloudflare Worker only, a vacuous pass here, not a skip), `npm run build`.
- Raster generation uses `cairosvg` (renders SVG → PNG) and `Pillow` (packs the multi-resolution
  `.ico`), both available in this environment. The generation script is a one-off (not committed as
  a build step) — only its output files are committed.

## Task Order & Rationale

Single task. The new `favicon.svg` is the source every raster asset is generated from, and
`app.html` only makes sense once every referenced file exists — there is no useful intermediate
checkpoint between drawing the mark and wiring it up.

## Task 1 — Redraw the favicon and ship the full icon set ✅

**Files:** `web/static/favicon.svg` (modify), `web/static/favicon.ico` (new),
`web/static/apple-touch-icon.png` (new), `web/static/favicon-32x32.png` (new),
`web/static/favicon-192x192.png` (new), `web/static/favicon-512x512.png` (new),
`web/src/app.html` (modify)
**Interfaces:** No component or route consumes these files programmatically — they are referenced
only by the `<link>` tags in `app.html` and fetched directly by the browser.

- [ ] Confirm the premise: in a scratch directory outside the repo (created and removed within this
      step, e.g. `mktemp -d`), render the current `web/static/logo.svg` path scaled into a 32×32
      badge and downsample to 16×16; observe it is not legible at 16×16. This is why the favicon is
      redrawn rather than a direct scale-down of the logo path (see spec's "Assumptions"). Remove the
      scratch directory when done.
- [ ] Replace `web/static/favicon.svg` with the composition from the spec's "Composition" section
      verbatim (rounded-square badge, three-chimney silhouette, `prefers-color-scheme` media query).
- [ ] Render the new SVG at 16×16 and 32×32 (dark scheme) and at 32×32 with the light-scheme colors
      swapped in a throwaway copy (same scratch directory as above); visually confirm the silhouette
      stays crisp and high-contrast at both sizes (per spec's Testing section). Remove the scratch
      directory when done.
- [ ] Write a one-off Python generation script (in the same scratch directory, not committed) that:
  1. Renders the dark-scheme `favicon.svg` via `cairosvg.svg2png` at 16×16, 32×32, 48×48, 180×180,
     192×192, and 512×512.
  2. Saves the 32×32/192×192/512×512 renders as `web/static/favicon-32x32.png`,
     `web/static/favicon-192x192.png`, `web/static/favicon-512x512.png`.
  3. Saves the 180×180 render as `web/static/apple-touch-icon.png`.
  4. Uses `PIL.Image.save(..., format="ICO", sizes=[(16,16),(32,32),(48,48)])` — from the 48×48
     render — to write `web/static/favicon.ico` as a genuine multi-resolution container.
- [ ] Verify the ICO is multi-resolution, not a renamed PNG:
      `python3 -c "from PIL import Image; im = Image.open('web/static/favicon.ico'); print(im.info.get('sizes'))"`
      must print all three sizes `{(16, 16), (32, 32), (48, 48)}`.
- [ ] Update `web/src/app.html`: replace the single `<link rel="icon" href="%sveltekit.assets%/favicon.svg" />`
      with the full tagged set from the spec's "`app.html` change" section verbatim (SVG first, then
      the `.ico` fallback with `sizes="any" type="image/x-icon"`, then the three sized PNG `<link>`s,
      then `rel="apple-touch-icon"`).
- [ ] Run `cd web && npm run check` — svelte-check + tsc must pass (no component code changed, so
      this should be a clean pass; confirms `app.html`'s markup is well-formed enough for the build).
- [ ] Run `cd web && npm run lint` — prettier must accept the reformatted `app.html`.
- [ ] Run `cd web && npm test` — vitest (Cloudflare Worker routing tests); expected to pass
      unchanged, confirming this touched nothing it covers.
- [ ] Run `cd web && npm run build` — confirms the static bundle still builds and copies
      `web/static/*` (including the new files) into `web/build`.
- [ ] Manual verification: `cd web && npm run dev`, open `http://localhost:5173` in a Chromium-based
      browser and in Firefox, and confirm the tab icon renders as the new mark (not a broken-image
      glyph) in both.
- [ ] Format and commit: `cd web && npm run lint -- --write` if needed, then rerun `cd web && npm run lint`
      to confirm it is now clean, then from the repo root
      `git add web/static/favicon.svg web/static/favicon.ico web/static/apple-touch-icon.png web/static/favicon-32x32.png web/static/favicon-192x192.png web/static/favicon-512x512.png web/src/app.html`
      and `git commit -m "web: design a favicon from the logo mark"`.
