# Milestone 1 — Auth + queue + console skeleton

Goal: a real multi-tenant MCP server that **two different coding agents** can authenticate
to and coordinate work through, with a console that manages members and repos.

Billing is recorded but not enforced. Trackers are reference-only (`ticket_ref` string);
the two-way sync engine is milestone 2.

Done means: from a fresh machine, a new user signs up with a passkey, registers a repo,
adds the server to Claude Code *and* Copilot CLI, and both sessions coordinate on the same
queue with tenant isolation proven by test.

## Task 6 — `of-auth`: TOTP + sessions ✅ (superseded — see below)

Originally shipped as: email verification, TOTP enrollment (encrypted secret, provisioning
URI), verification with drift + replay refusal, recovery codes, magic-link recovery, rate
limiting, constant-shape login responses. Browser session cookies for the console.

`login` was the front door: it normalized the address, throttled on both address and source
IP, and answered identically for an unknown address, a disabled account, a wrong code, and a
replayed one — the unknown path ran the same TOTP arithmetic and wrote the same audit row.
`magic` issued single-use ten-minute links (verify / recover / invite), matching purpose in
the lookup so a verification link could not be spent on recovery. `sessions` was, and
remains, the console cookie: hashed at rest, a sliding 14-day idle window under a hard 90-day
cap, dead the moment its user is disabled.

**This was superseded in two follow-on changes, neither of which has its own committed
spec — recorded here since this is where the drift would otherwise sit.** `Remove email
from the product` (`0009_no_email`) deleted `of_auth::magic`, `of_web::mail`, the `Mailer`
trait, `LogMailer`, the `magic_links` table, `users.email_verified_at`, and the `/verify`
and `/recover` console pages: otto-factory sends no mail, an authenticator app was the only
factor, and an org admin clearing a member's credential became the only assisted recovery
path. `Replace TOTP with passkeys` (`0010_passkeys`) then replaced TOTP itself: `passkeys`
holds public keys and counters rather than an encrypted shared secret, sign-in is
usernameless (`allowCredentials` empty, the browser resolves the account), and recovery is
a second passkey — `passkeys::remove` refuses to delete the last one. Signup now takes no
request body at all, which is what closes the account-enumeration oracle that both a
password and a returned TOTP secret used to leak through. See
[`CLAUDE.md`](../../CLAUDE.md)'s Authentication section for the mechanism as it stands
today, and [`docs/clients/matrix.md`](../clients/matrix.md) for what each client actually
sends against it.

## Task 8 — `of-mcp`: server + tools ✅

`rmcp` Streamable HTTP mount, resource-server middleware (audience enforcement, principal
injection, `401` + `WWW-Authenticate` discovery hint), then the tool surface from the spec.
Tool descriptions written for an LLM caller with no docs.

**27 tools**: repos (4), jobs (13), coordination (9), `whoami`. `usage` and `whoami`'s
quota field belong to task 9; `link_ticket` and `sync_ticket` are milestone 2, since
milestone 1 keeps trackers to the `ticket_ref` string.

Decisions worth carrying forward:

- **The principal is per request, not per session.** An MCP session spans many HTTP
  requests and the token is re-introspected on each one, so revoking a token in the console
  stops it on the agent's next call rather than at some unbounded later point.
- **The transport is stateless** (`stateful_mode: false`, `json_response: true`). Nothing
  is ever pushed to a client — `watch` is a long poll the agent initiates — so a
  server-held session would buy nothing and cost sticky routing across replicas.
- **`rmcp` defaults `allowed_hosts` to loopback**, which silently rejects every request to
  a hosted server. `Config` requires it.
- **Every result is a one-field object** (`{"job": …}`, `{"jobs": […]}`). MCP requires an
  `outputSchema` rooted at `object`, so a bare array is not a legal result — and an
  envelope can gain a field later without breaking callers.
- **`of-core` now derives `JsonSchema`** alongside the `Serialize` it already had, so tool
  results describe themselves without a parallel set of view types to drift.

`Watcher` gained `shutdown()`: `PgListener` detaches a connection from the pool that
nothing was reclaiming. That is a graceful-shutdown leak in production and a hang in tests,
where the throwaway database cannot be dropped while a session is still attached.

## Task 9 — `of-billing`: recording ✅

`usage_events` write + `org_period_usage` increment inside the tool's transaction, the
free/billable classification table, and the `usage` tool. Enforcement is behind a flag,
default off. `whoami` gained its `usage` field.

The split with `of-core`: every statement against a tenant table lives in `of_core::usage`
and goes through a pinned `Tx`; `of-billing` owns the policy — which tools cost anything,
what a bucket is worth, when a call is refused. That keeps the interesting decisions
unit-testable with no database at all.

Decisions worth carrying forward:

- **The meter runs before the work, not after**, immediately after the tool opens its
  transaction. That looks backwards for "a failed call is not billed" and is exactly what
  makes it true: the usage row is in the tool's own transaction, so a failure rolls the
  meter back with it. Charging afterwards would need a second transaction that can fail,
  be retried, or be forgotten. It also puts the quota check where a refusal is cheapest.
- **`watch` is the exception** and meters in a transaction of its own, committed before
  the wait. Holding a transaction open for thirty seconds per idle agent would exhaust
  the pool long before the queue was busy. It is free, so there is no billing consequence.
- **Unclassified tools are free, loudly.** The asymmetry is the point: defaulting to
  billable means a tool nobody priced silently charges customers, and the first person to
  notice is one reading a bill. `classify::exhaustive_over` turns it into a test failure —
  `every_tool_has_a_price` compares the router against the price list.
- **Lease renewal and release are free**, alongside the reads. Charging per renewal bills
  an agent for holding still; charging for release creates an incentive not to release,
  which costs everyone else the branch until it expires. Coordination hygiene must not
  have a price on it.
- **Enforcement refuses billable work and never reads.** An org that runs out mid-task can
  still see its queue, understand what happened, and go and upgrade.

**Not done, and deliberately deferred**: the design's "at 80% of the bucket the server
attaches a warning to tool results and emails org admins". The threshold and the `warning`
flag exist and are reported by `usage` and `whoami`; threading a notice through all 29
tool result envelopes, and the admin email, are milestone 2. The plan's own scope for this
task did not include them.

## Task 10 — `of-web`: console API ✅

Session auth, org/member/team/repo CRUD, invites, PAT mint/revoke, usage read, the audit
trail, an OpenAPI document, and — at the time this task shipped — magic-link delivery.
Magic links were removed by the later `Remove email from the product` change (Task 6);
invitations are now single-use codes the admin hands over themselves, never emailed. Both
rules the plan attached to this task still hold, and both are asserted rather than trusted:
`every_single_use_redemption_is_a_post` and `the_cookie_carries_every_attribute_that_protects_it`.

**It also carries the authorization server's HTTP surface** — `/oauth/authorize` (consent
page and decision), `/oauth/token`, `/oauth/register`, `/oauth/revoke`, and both
`.well-known` documents. Task 7 built the AS as pure logic with no transport, and nothing
else in the plan owns mounting it; it landed here because `/oauth/authorize` is a browser
surface that needs precisely the session cookie this task builds. That is the same fact the
plan's own `SameSite=Lax` note was pointing at.

**`of-core` needed two modules first**, which tasks 3–5 had not covered: `teams` (CRUD,
rosters, resolution) and `invites` (mint, list, revoke, peek, accept). Both are tenant
tables with cross-org negative tests in `isolation.rs`, per the rule in `CLAUDE.md`.

Decisions worth carrying forward — **note: the several bullets below about mail delivery,
verification links, and TOTP describe design decisions for a mechanism that no longer
exists.** `Remove email from the product` and `Replace TOTP with passkeys` (see Task 6)
deleted `of_web::mail`, the `Mailer` trait, `LogMailer`, and the verification-link flow
entirely; they are kept here as the historical record of the reasoning at the time, not as
a description of the current system:

- **A verification link opens a session only while the account has no confirmed TOTP.**
  Something has to break the bootstrap circle — logging in needs a second factor, enrolling
  one needs a session. Before enrollment, control of the mailbox *is* the strongest factor
  the account has and the same one the user would present anyway; the moment an
  authenticator exists the link stops being enough, so a verification mail opened later on
  a phone marks the address verified and nothing more. `of_auth::login::verify_email`
  deliberately opens no session and leaves this decision to the caller.

- **An org you are not in is `404`, never `403`.** A `403` on a real slug and a `404` on a
  fake one turns any signed-in account into a directory of who uses the product. Both
  collapse in `session::OrgCtx`, which is also where membership and role are decided —
  once, in an extractor, rather than in each handler where forgetting is invisible.

- **The router and the OpenAPI document are built from one list.** `catalog.rs` declares
  each endpoint with its handler *and* its prose; `router()` folds it into axum and
  `openapi::document` renders it. Drift is not detected, it is impossible. The honest cost:
  component schemas are hand-written, so a new field on a response struct does not appear
  in the document by itself.

- **Removing a member revokes their tokens for that org and nothing else.** Their sessions
  and their tokens in other orgs survive — a session is not org-scoped, and signing someone
  out of an unrelated customer's console is not that button's business. `of-auth` gained
  `tokens::revoke_all_in_org` for it.

- **`RepoPatch::team_id` is `Option<Option<TeamId>>`.** Found by a test: with a plain
  `Option`, "absent" and "clear it" collapse, so a team-scoped repo could never be
  unscoped — and since `delete_team` refuses while repos still reference it, the team
  became undeletable. Absent / set / clear are three states and the type now says so.

- **OAuth protocol errors keep their own words.** Identity failures collapse to
  `AuthError::public`, which is the enumeration defense; `invalid_scope` and friends
  describe the caller's own request, so RFC 6749 §5.2 returns them verbatim and so do we.
  Also found by a test — the first draft flattened `unknown scope "jobs:destroy"; supported
  scopes are …` down to the bare word `invalid_scope`.

- **The consent screen leads with the redirect host.** Registration is open, so anyone can
  register a client called "Claude Code"; the name is rendered as the untrusted string it
  is (escaped, and asserted escaped), and the host the code will actually be delivered to
  gets the visual weight. Every issuable scope has a sentence a person can weigh, enforced
  by `every_issuable_scope_is_explained_in_words`.

- **Mail delivery is a trait, and the trait is the deliverable.** A provider needs an
  account, a verified sending domain, SPF/DKIM, and a bounce policy — deployment decisions,
  not crate decisions. `LogMailer` is loud on purpose: a quiet no-op mailer is
  indistinguishable from a working one until somebody asks why nobody has joined.

- **No transaction is held open across a mail send.** An invitation is written, committed,
  and then mailed; a failed send withdraws it. The tidier-looking order — commit only after
  a successful send — would pin a pooled connection to someone else's SMTP latency, which
  is the same trade `watch` refuses in task 9. The cost is a brief window where a live
  invitation exists that nobody has received, which is harmless: it is single-use, it
  expires, and a retry supersedes it.

- **`throttle_by_source` is charged before the address is looked up.** Charging it only on
  the path that actually sends would make the throttle itself an enumeration oracle — an
  attacker would watch their own budget move and learn which addresses exist.

**Deferred, deliberately**: enterprise OIDC federation and domain claiming (the console
routes for `idp_connections` / `claimed_domains`), and org deletion. Neither is in this
task's scope and both need decisions — DNS verification flow, what deleting an org does to
its job history — that milestone 1 does not have to make.

## Task 11 — `web/`: Svelte 5 console ✅

SvelteKit 2 + Svelte 5 runes + Tailwind v4, TypeScript strict. Signup → verification →
TOTP enrollment → org creation, then members and invitations, teams, repos with live
leases, a read-only queue with job detail, the usage meter, an admin-only audit log, and a
"connect an agent" page that renders the exact configuration for Claude Code, Copilot CLI,
Cursor, Codex, and any other MCP client — plus PAT minting and revocation.

Verified end to end in a browser against the real router, at the time this task shipped:
signup → emailed link → verify page → enrollment (QR, recovery codes, confirmation) →
create an org → console; and separately the recovery-link path, the token mint, the lease
view, the team-delete refusal, and a signed-in account's view of an org it does not belong
to. **This flow no longer exists**: the later `Remove email from the product` and
`Replace TOTP with passkeys` changes (Task 6) replaced it with a passkey ceremony —
signup takes no body, there is no verification email and no TOTP enrollment step, and
sign-in is usernameless. See [`CLAUDE.md`](../../CLAUDE.md)'s Authentication section for
the flow as it stands today.

**It is a single-page app, and that is a security decision.** The session is an
`HttpOnly`, `__Host-`-prefixed cookie bound to one origin. A SvelteKit server rendering
these pages would have to hold that credential to fetch on the user's behalf — a second
process with the keys to every console session, for pages behind a login that cannot be
cached anyway. `adapter-static` with an `index.html` fallback keeps the cookie in exactly
one place and makes CORS a non-question. It also decides the dev setup: Vite *proxies*
`/api`, `/oauth`, and `/.well-known` rather than pointing `fetch` at another port, because
a cross-port request would not carry a `__Host-` cookie and no CORS header could rescue it.

**Org pages live under `/o/[org]`**, not `/[org]`, so no org slug can collide with a page
name. The paths the server names — `/login`, `/invite/{org}`, `/settings/billing` — are
fixed by what the server puts in an invitation code and in `of-billing`'s upgrade prompt.
(`/verify` and `/recover` existed at the time this task shipped, when signup delivered an
emailed link; both were removed along with email — see Task 6.)

**Three read-only queue endpoints were added to `of-web` for this** — `GET
/api/orgs/{org}/jobs`, `.../jobs/stats`, and `.../jobs/{job}` — because the console had no
way to see a queue at all. They are `GET`-only and a unit test
(`the_queue_is_read_only_over_the_console`) fails if a write ever appears under `/jobs`: a
job is created and finished by the agent doing the work, and a human pressing "mark
complete" in a browser would be telling the queue something they cannot observe. Filters
name repo and team *slugs*, and an unregistered one is an error listing what is registered
rather than an empty table that reads as a quiet queue.

**`resolve_repo` was fixed while wiring that up.** An explicit slug that did not exist
returned a bare `repo_not_found`, while a remote that matched nothing returned
`repo_unresolved` *listing the registered slugs* — even though the function's own doc
comment and constraint 1 promise the latter in both cases. A mistyped slug is the
commonest way to reach that error and the one the caller can actually fix from the answer.
An explicit slug stays authoritative: a slug that misses now stops with the listing error
rather than falling through to a remote the caller also supplied, because an agent that
passes its checkout's remote alongside a repo name would otherwise get the repository it
happens to be sitting in every time it typos the name. Both variants already mapped to
`404`, so the only change a caller sees is a better message and the `repo_unresolved` code.

**Not done, deliberately**: no OAuth consent styling (the consent screen is server-rendered
HTML in `of-web` and stays there), no tracker or IdP binding UI (milestone 2), and no
`web/` step in CI, because there is no CI (task 1).

## Task 12 — Client conformance ✅

Claude Code 2.1.258 and Copilot CLI 1.0.82, driven against `cargo run -p of-server` with a
real Postgres, over both paths. The findings, the traces, and the re-run instructions are in
[`docs/clients/matrix.md`](../clients/matrix.md); what follows is what the run changed.

The milestone's "done means" is executed rather than argued: Claude Code (OAuth, org owner)
queued two jobs, claimed one and took a lease on `widget@main`; Copilot CLI, authenticated
as a *second* invited user on a PAT, called `ready`, claimed the other job, was refused the
lease with the holder and expiry named, messaged the first user by address, and completed
its own job. One `usage` counter saw both: 27 calls, 12 billable.

**The one blocker was a rule that had been decided on paper.** Registration refused
`http://localhost:<port>/callback` — `localhost` was deliberately outside the RFC 8252 §7.3
loopback carve-out, on the reasoning that a name resolves and a literal address does not —
and that is the exact string Claude Code registers. The consequence was not a degraded flow
but no flow: a `400` at registration, before consent could be reached. `localhost` now sits
in the carve-out with `127.0.0.1` and `[::1]`, port ignored and everything else exact, and
the string Claude Code sends is a test case. The security argument that replaced the old one
is in `redirect_uri_matches`: anyone who can point `localhost` elsewhere already owns the
machine the agent runs on, and the code they would intercept is worth nothing without the
PKCE verifier. Copilot registers `http://127.0.0.1:<ephemeral>/` and was never affected —
which is exactly how a rule like this survives review and still ships broken.

**`watch` reported the timeout it was given as the time it had waited.** A poll woken after
22 seconds answered `waitedSeconds: 30`. The only reader of that field is an agent pacing
itself, so it now reports measured elapsed time and the wake-up test asserts the difference.

**Three things the run found and deliberately did not change**, because each is a decision
rather than a defect: `complete_job` and `fail_job` check the status but not the claimant,
so one agent can finish another's job; a lease is held by a *user*, so two agents on one
account share lease identity and the second acquire renews rather than conflicts; and
unknown tool arguments are dropped silently, so an LLM guessing `body` for `description`
loses the field and is told nothing. The matrix carries the argument for each.

**Cursor and Codex CLI were not run** — neither is installed on the conformance machine.
Nothing in the server distinguishes them, and both mechanisms they would use (loopback
dynamic registration, or a bearer header) are exercised by clients that are installed.

## Task 13 — Deploy 🚧

`of-server` now binds a port and serves every surface on it: `Config::from_env`, migrations
at startup, `/healthz` and `/readyz`, structured logging, graceful shutdown, the console
bundle, a `Dockerfile`, and `fly.toml`.

**Remaining**: the first live deploy. Everything is built and verified locally — the image
builds and the binary serves — but nothing has been pushed.

The target itself already exists, which the merge with `origin/master` established: the Fly
app is `otto-factory-mcp` in org `savvagent`, with a dedicated `otto_factory` database on the
shared `savvagent-pg` cluster and `DATABASE_URL` already staged as a secret by
`fly mpg attach`. So what is left is `fly deploy` and confirming `OF_PUBLIC_URL` /
`OF_RESOURCE_URI` against whatever hostname the console ends up on — which is a different
answer if Cloudflare fronts it.

Putting Cloudflare in front of the console is worked out and verified locally in
[`docs/deploy/cloudflare.md`](../deploy/cloudflare.md) (issue #2): one Worker serves the
bundle and proxies the API, so the browser still sees one origin. Two settings there are
part of *this* task and fail quietly without it — `OF_ALLOWED_HOSTS` must name the origin's
own hostname, and the origin must refuse traffic that did not arrive through Cloudflare
before `OF_CLIENT_IP_HEADER=cf-connecting-ip` means anything.

**Route collisions are a startup panic, so a test builds the router.** `of-web` and `of-mcp`
both serve `/.well-known/oauth-protected-resource` — `of-web` because it sits beside the
authorization server's own document and the OpenAPI document describes it, `of-mcp` because
its `401` challenge points at it and a pointer into another crate's router goes stale the
first time the surfaces are split. Both call the same function with the same configuration,
so the documents are identical and which one wins does not matter; what matters is that
`Router::merge` panics rather than choosing. `of_mcp::mcp_endpoint` is `router` without the
discovery route, and `the_whole_router_assembles` reaches the panic before a deploy does.

**The SPA is the fallback everywhere except the API.** `index.html` answering an unknown
path is what makes a hard refresh of `/o/acme/queue` work. `index.html` answering
`/api/no/such/thing` with `200 text/html` is what makes an agent retry forever against a
route that will never exist, so the four API prefixes get a JSON `404` instead. The prefix
check is segment-aware: `/apiary` is a legal org slug and belongs to the console.

**`/healthz` never touches the database; `/readyz` always does.** They answer different
questions. A liveness probe decides whether to *kill* a process, so pointing one at the
database turns a thirty-second blip into a simultaneous cold start of every replica against
a database that is already unwell. Readiness decides whether to *route* to a replica, and
the answer while the database is unreachable is no. Fly's check is on `/readyz`.

**`Config::from_env` never falls back quietly.** A variable that is set but unparseable is a
startup error naming it — `OF_ENFORCE_QUOTAS=yes-please` silently reading as "off" is how a
billing control gets deployed switched off for a year. `OF_PUBLIC_URL` and
`OF_ENCRYPTION_KEY` have no defaults at all, because a wrong value for either fails
*silently*: links that go nowhere sitting in somebody's inbox, tokens minted for an audience
nothing accepts, or — for a generated-at-startup key — every enrolled authenticator
unreadable after a restart.

**A proxy change came out of the deploy, and it is a security fix.** `of-web`'s
`trust_forwarded_for: bool` became `client_ip_header: Option<String>`. The old shape assumed
the trustworthy header is always `X-Forwarded-For`, and behind Fly's proxy that is false:
fly-proxy *appends* rather than overwrites, so a caller sending `X-Forwarded-For: 1.2.3.4`
arrives as `1.2.3.4, <real address>` and the left-most entry — the one every convention calls
the client — is the one the attacker chose. Turning the old flag on under Fly would have
made every per-IP throttle keyable by the caller, which is worse than having none because it
looks like it is working. Only the named header is read, with no fallback to another one:
falling back to `X-Forwarded-For` when `Fly-Client-IP` is absent would hand the value back to
anyone who can make the proxy drop it.

**`into_make_service_with_connect_info` is not decoration.** `client_ip` reads the peer
address out of `ConnectInfo`, so serving without it returns `None` for every request and
silently disables rate limiting on login and on client registration. Verified against the
running binary: a signup writes the rate-limit bucket `link:127.0.0.1`.

Verified end to end against the real binary: migrations applied to a fresh database, both
discovery documents served, `POST /mcp` challenging with a `resource_metadata` pointer at
this origin, the console and a deep link rendering, an unknown API path answering JSON, a

## Rule for every task

A task is done when its tests pass, `cargo clippy --all-targets -- -D warnings` is clean,
and `cargo fmt --all --check` is clean. Tenant-scoped functions are not done without a
cross-org negative test. Anything touching `web/` adds `npm run check` and `npm run lint`,
which are that half of the tree's `cargo test` and `cargo fmt --check`.
